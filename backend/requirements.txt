# geny-executor 2.2.0 — "Environment is the single source of truth"
# release. Fixes the prod bug where manifest strategy_configs were
# silently dropped (empty evaluation chain terminated the worker loop
# after one iteration); adds build_manifest/validate_manifest, the
# session lifecycle surface (aclose/refresh_runtime/ModelOverrides),
# the typed event contract + pipeline.events() tap, full streaming
# chunk forwarding, manifest-expressible subagents+memory, and the
# embedding-credential bundle channel with a 401 circuit breaker.
# Geny compat verified zero-regression vs 2.1.4.
#
# 2.5.0 — token-budget guard compacts-and-rechecks instead of
# hard-failing: the guard now measures the projected next request
# (system+messages+tools) and, on pressure, compacts history + re-checks
# before rejecting. Geny's PersistingLLMSummaryCompactor is auto-wired
# into the guard recovery path (no code change) and marks
# persists_own_compaction so the snapshot isn't recorded twice.
#
# geny-executor 2.67.0 — one Responses wire.
#
# OpenAI refuses function tools on a reasoning model unless reasoning is
# switched off outright, so an agent on gpt-5 could not take a turn. Those
# turns now go to the Responses API, which carries tools and reasoning
# together, over the same wire the Codex subscription already used.
#
# geny-executor 2.68.0 — the backend that owned the loop is gone.
#
# BREAKING for us, and we made the matching changes: attach_runtime no
# longer takes ``containerize_cli`` (an attached sandbox is a TOOL
# surface and nothing else), ``ClientCapabilities`` lost
# ``is_subprocess`` / ``supports_mcp_passthrough``, and the
# ``api.cli_tool_call`` event can no longer fire. The ``claude_code_cli``
# provider is unregistered — every environment already names
# ``geny_router`` (migrate_to_router, at boot), and the same binary is
# driven as a pure LLM by ``geny_claude_code``.
#
# geny-executor 2.68.1 — the sandbox now actually reaches the tools.
#
# attach_runtime(sandbox=) stamped the handle on the Tool stage context,
# but Stage 10 rebuilt a fresh ToolContext per dispatch and dropped it.
# So every sandboxed session ran Bash/Read/Write/Edit/Grep/Glob on the
# HOST while its prompt said /workspace — the agent's first tool call was
# refused, every time, and it recovered by reading the host path out of
# the error. Nothing to change here; the pin is the fix.
#
# geny-executor 2.69.0 — Claude Code through the official Agent SDK.
#
# Fourteen hand-built `claude -p` flags (and a table of flags learned at
# runtime from "unknown option" stderr) became typed options. Auth is
# unchanged — the SDK drives the same binary, so per-account
# CLAUDE_CONFIG_DIR still gives each login its own OAuth.
#
# geny-executor 2.70.0 — one conversation, any provider, at any point.
#
# Fixes a session that could die when its model changed: the Anthropic
# translator replayed thinking blocks, which are bound to the model that
# produced them, so a block written by one account's model reached the
# next account's. Also adds real load balancing — interchangeable hops
# (same provider AND model) take turns least-recently-used instead of
# hop 0 answering until it hits its cap.
#
# Must match the version pin in backend/pyproject.toml — out-of-sync
# pins are what caused the prod Docker build to install 1.21.0 and
# blow up on `from geny_executor import CredentialBundle`.
# geny-executor 2.72.1 — an endpoint says what it serves, and the
# saying is enforced (supports_tools=False used to change the flag
# and send the tools anyway, so the settings switch below would have
# been a switch that does nothing).
#
# One client class reaches OpenRouter and a laptop's llama.cpp, so it has
# to declare the weakest of them. 2.71.0 made vision opt-in and thereby
# turned every image sent through OpenRouter into a placeholder; 2.72.0
# lets the account declare its endpoint (``extras["capabilities"]``), and
# fixes the image a TOOL returned, which the 2.71.0 lowering never saw
# because it lives nested inside the tool_result.
#
